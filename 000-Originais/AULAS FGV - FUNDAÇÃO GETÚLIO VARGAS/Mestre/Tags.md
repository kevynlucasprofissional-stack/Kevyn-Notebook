fluxo ágil de decisão:
O que é isso? → tipo/
Em que fase está? → fase/
Isso requer alguma ação? → ação/
Tem um tema específico? → tema/
Quero memorizar isso? → flashcards

Regra: Só criar uma etiqueta de tema caso haja 5 notas fixas sobre o tema.
Regra: Uma nota pode ter apenas um tipo, escolha com base no tipo dominante da nota.

| Etiqueta        | Significado                                                     | Exemplos de uso                               |
| --------------- | --------------------------------------------------------------- | --------------------------------------------- |
| `tipo/fonte`    | Anotações tiradas de uma fonte externa                          | Resumos de livros, vídeos, artigos            |
| `tipo/estudo`   | Anotações de aprendizagem ativa                                 | Mapas mentais, resumos próprios               |
| `tipo/projeto`  | Anotações relacionadas a projetos em andamento                  | Planejamento de vídeos, campanhas, etc        |
| `fase/fugaz`    | Anotações soltas, ideias cruas                                  | Anotações rápidas de brainstorm               |
| `fase/ativa`    | Nota em desenvolvimento                                         | Texto rascunhado, incompleto                  |
| `fase/fixa`     | Conteúdo consolidado e organizado                               | Artigos prontos, roteiros finalizados         |
| `ação/tarefa`   | Algo a ser feito (to-do)                                        | "Editar vídeo X", "Responder cliente"         |
| `ação/meta`     | Um objetivo maior                                               | "Alcançar 10k seguidores", "Terminar curso X" |
| `ação/revisar`  | Algo que precisa ser revisado                                   | Revisar um artigo antes de publicar           |
| `ação/exportar` | Algo que precisa ser enviado, publicado ou compartilhado        | Publicar post, mandar para cliente            |
| `flashcards`    | Notas que contém conteúdo para revisão em formato de flashcards | Definições, conceitos, fórmulas               |

## 📌 Regra Absoluta para Nunca Errar as Tags + Evitar Over Engineering:

### **"Tag só serve pra ação rápida. Se você precisa pensar mais de 5 segundos pra escolher, é porque ela não deveria existir."**

---

### ✅ Tradução prática dessa regra:

1. **Cada etiqueta deve responder a uma pergunta objetiva, simples e recorrente.**
    

|Pergunta|Exemplo de resposta/tag|
|---|---|
|O que é isso?|`tipo/estudo`|
|Em que fase está?|`fase/ativa`|
|Tem alguma ação pendente?|`ação/revisar`|
|Faz parte de algum tema recorrente?|`tema/marketing` (se tiver 5+ notas fixas)|

---

2. **Se você começar a criar tags só porque “talvez um dia seja útil”… DELETE.**
    

👉 Só crie tag se **já existir mais de 3 notas que precisem dela agora**, ou uma regra objetiva (como seu "5 notas fixas" pra tema).

---

3. **Regra de 3 Clássica para criação de novas tags:**
    

✅ Existe uma pergunta clara que essa tag responde?  
✅ Já tenho pelo menos 3 notas que realmente precisam dessa tag?  
✅ Vou usar essa tag pra filtrar ou buscar algo dentro dos próximos 7 dias?

👉 Se a resposta for **NÃO** pra qualquer uma… **não crie a tag.**

---

4. **Se tiver dúvida entre duas tags → escolha a mais útil pra filtragem futura.**
    

Exemplo:  
Se você está na dúvida entre `ação/tarefa` e `ação/revisar`, pense:  
"Na prática, quando eu abrir o Dataview, eu quero encontrar essa nota em qual lista?"

Se a resposta for "na lista de coisas pra revisar" → vá de `ação/revisar`.  
Se for "na lista geral de tarefas" → vá de `ação/tarefa`.

---

5. **Mantra final:**
    

> **"Tag é filtro. Se não for útil pra filtrar ou buscar, é só enfeite. E enfeite não sobrevive em sistema vivo."**
